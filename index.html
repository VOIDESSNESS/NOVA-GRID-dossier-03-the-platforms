01 — Platform Philosophy

Why Three Platforms?
Because One Cannot
Serve All Truth.

Every person interacting with Nova Grid has a different relationship with power. A household mother needs to feel in control. A grid operator managing a fault needs dense, precise data and immediate decision support. An executive needs strategic altitude. These require three completely different interfaces.

The failure mode of most utility platforms is building one interface that attempts to serve all users — and ends up serving none well. Nova Grid's three-platform architecture is a deliberate rejection of this. Each platform answers one question: what does this person need to feel empowered in their role?

02 — Design Principles

Six Laws That
Govern Every Pixel

These principles govern every design decision across all three platforms. They are not aesthetic preferences — they are functional requirements derived from building digital infrastructure for Nigeria.

01
Clarity Over Cleverness
Every element has a single unambiguous purpose. We serve users across varied digital literacy levels. If it needs explanation, it needs redesign.
02
Trust Through Transparency
Nigerians have been failed by opaque utility systems for 60 years. Every platform shows its work — where power comes from, where money goes, what NEXUS decided and why.
03
Speed Is a Feature
Network conditions in Nigeria are variable. Critical functions (power toggle, balance check, payment) must work on 2G. Data loads progressively without blocking core functionality.
04
Intelligent by Default
NEXUS AI is the foundation platforms are built on — not a feature added to them. Every screen surfaces AI insight appropriate to the user's role.
05
Accessible to All Nigerians
Customer platform works on a Tecno Spark. Readable in direct sunlight. Functional with one hand on a danfo bus. WCAG 2.1 AA compliance minimum.
06
One System, Three Voices
All three platforms share the same token set — type scale, spacing system, iconography. A staff operator and a customer both recognise Nova Grid ecosystem, though their experiences differ completely.
03 — The Design System

One Token Set.
Three Surfaces.

A design system is the invisible infrastructure of consistency. Nova Grid uses a single token set — spacing, colour, typography, component behaviour — shared across all three platforms.

Spacing Scale — 4px Base Unit

All spacing across all three platforms is a multiple of 4: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96px. This creates visual rhythm without visual rigidity. Cards in the customer platform use 22–24px internal padding; the staff platform uses 14–16px for information density.

Border Radius Scale

More rounding = more consumer-facing. Customer platform: 14–24px cards. Staff platform: 8–12px. Management: 12–16px (premium but not casual). The radius language communicates the relationship between the platform and its user without words.

Motion Principles

Three animation categories: (1) State transitions — power toggle pulse, theme switch (200–300ms); (2) Data loading — progressive content reveal; (3) Attention signals — pulsing dots for live data, critical alerts. Easing: ease-out for entrances, ease-in for exits.

Icon System

Prototypes use Unicode emoji for maximum compatibility and zero load overhead — enabling instant stakeholder recognition during review. Production replaces these with Nova Grid Icons: a custom SVG set maintaining identical semantic meaning with precise visual style consistency across all three platforms.

Component Library

Shared React component library (Nova Grid UI) provides the same base components — Card, Button, Chart, Modal, Tag — to all three platforms. Each platform applies its own token set to these components. The same <Button variant="primary"> renders teal on the customer platform, indigo on staff, and gold on management — one component, three identities.

Responsive Strategy

Customer: Mobile-first. Single breakpoint at 768px transforms bottom nav → sidebar, expands charts. Staff: Desktop-only. Minimum viewport 1280px. No mobile layout. Management: Fixed large display. Optimised for 55–75" 4K panels at the National Command Centre.

07 — Customer UX Decisions

Every Decision
Defended.

The Mobile-First Layout

Nigeria's internet users access the web predominantly through smartphones. The customer platform is designed mobile-first — the mobile layout is the primary design; desktop is an enhancement. When the screen exceeds 768px: bottom navigation disappears, a left sidebar emerges, content expands, charts grow taller. This is a complete layout philosophy change — not just a resize.

Bottom Tab Navigation

Five tabs (Home, Control, Usage, Pay, Grid) accessed with one thumb tap from anywhere. Positioned at the bottom because that is where Nigerian users' thumbs naturally rest on their phones. The five choices cover every core user action — no user should ever need to search for a function.

Dark Mode Default / Light Mode Design

Dark is default — OLED screens (common on Nigerian mid-range phones) consume significantly less battery in dark mode. Critical for users with intermittent charging access. Light mode is independently designed for outdoor legibility. Both modes pass WCAG contrast requirements independently — they are not approximations of each other.

The Power Toggle Design

Nigerians have never had control over their power supply. Giving them a button that controls it must feel powerful and irrevocable — like a real switch, not a software toggle. Large circular button, confirmation state for OFF, animated teal pulse when active, the card border shifts colour, the live wattage reading only appears when powered. The visual language communicates state without text.

Payment as Fintech

The payment system is styled as a premium fintech product, not a utility bill portal. Nigerians are sophisticated fintech users who trust Kuda, Piggyvest, and Flutterwave. The wallet card has a gradient, large balance display, and card metaphors. This increases comfort with storing money in the platform — making auto-recharge adoption higher and advance payment possible.

Dashboard Design Constraint

The dashboard answers exactly five questions: Is my power on? How many units remain? How much did I use today? What is my wallet balance? Is there anything wrong with the grid near me? Nothing else appears on the dashboard. This constraint is the design.

Why Desktop-Only?

Grid operations require sustained attention, multi-panel awareness, and interaction precision that a touchscreen phone cannot support. Operators work at fixed multi-monitor workstations in zone control centres. A mobile staff app would compromise information density and create unacceptable security risk — personal phones accessing sensitive infrastructure data and customer records.

Information Density

Smaller font sizes (12–13px body vs 14–15px customer), tighter padding, more compact cards. Appropriate for trained professionals using a tool for 8–12 hour shifts. Tables are the primary data format — sortable, searchable, dense. The customer database table shows 8–10 rows with 8 data points each simultaneously — impossible and unnecessary on the customer platform.

The Three-Column Architecture

The persistent right panel (300px) shows NEXUS system status, live alerts, and NEXUS AI chat at all times — regardless of which tab the operator is working in. Operators never lose situational awareness by navigating to another view. NEXUS status is ambient, always present, never requiring navigation.

The Ticket System Design

Each ticket shows NEXUS's diagnostic work alongside the complaint: root cause analysis, confidence score, automated actions already taken, and specific staff actions required. The operator reviews, approves, escalates, or overrides. NEXUS does the analytical work; humans provide judgment on the exceptions. This architecture enables 94% autonomous resolution while preserving human oversight for the remaining 6%.

09 — NEXUS in the Staff Platform

The AI That
Explains Itself

The most dangerous AI system is one that acts without explanation. Every automated action NEXUS takes is logged, explained in plain language, and presented to the human operator before they are asked to confirm escalation or override.

On the staff platform, NEXUS speaks in three distinct visual contexts: (1) the right panel chat — for direct operator queries; (2) ticket diagnosis blocks — embedded in each ticket's detail view; (3) the alert feed — real-time notifications of automated actions. All three use purple (#A78BFA) — purple never appears for human-generated content, creating an unmistakable visual grammar for AI vs human.

When NEXUS takes a significant action — isolating a fault segment, applying customer compensation, flagging fraud — the staff platform shows a card styled: "NEXUS ACTION · [timestamp] · [description] · Confidence: [%]". This is not a buried audit log entry. It is a prominent, human-readable announcement of what the AI did and why — in the operator's active work context. This is what makes NEXUS trustworthy rather than merely capable.

The Nigeria Grid Map

The centrepiece of the Grid Command view is a custom SVG map of Nigeria divided into the six geopolitical zones, colour-coded by real-time grid health: green (stable), amber (high load), red (fault active). Each zone is clickable for drill-down. Transmission lines animate as dashed paths showing power flow. A fault causes the animation to pause and a red pulse indicator to appear on the affected segment. Designed for two audiences: the executive needing spatial awareness, and the investor for whom a map is the most immediately comprehensible view of national infrastructure scale.

Gold Accent Psychology

The gold accent on the deepest black background of the three platforms is deliberate investor-psychology design. Gold signals value, stability, and institutional quality. Every design choice at the management level asks: "Would this look credible on a 120-inch screen in a boardroom?" The answer determines every spacing, type size, and colour decision.

What the Platform Intentionally Omits

The management platform has no ticket queue, no customer search, and no manual power toggle. These are deliberate absences. Leadership manages zones, not individual customers. Their interface shows patterns — average resolution times, zone-level performance, NEXUS autonomy rates — not individual tickets. If a CEO is debugging individual customer tickets, the organisation has failed. The platform's design enforces appropriate role boundaries.

NEXUS Intelligence View

The Intelligence tab surfaces NEXUS's strategic recommendations — demand forecasting, capacity expansion recommendations, fraud pattern analysis, and financial projections — formatted for executive decision-making, not technical analysis. NEXUS presents its recommendations with estimated cost, revenue impact, timeline, and confidence level. Management reviews, challenges, and approves. The AI proposes; the CEO decides.

Between Layers

All three platforms communicate with NEXUS through a unified API gateway. Role-based access control at the API layer means the customer endpoint returns a fundamentally different data model than management — even for the same underlying data.

13 — Security Model

Security by Architecture,
Not by Compliance.

Nova Grid manages power for 45 million Nigerians and handles billions of naira in daily transactions. Security is not a feature — it is the foundation everything else is built on.

L1
Physical Air Gap
NEXUS grid control (OT network) is physically air-gapped from all internet-connected systems. No API call from any platform can directly affect grid hardware. Control commands pass through a hardened DMZ with one-way data diodes. A compromised customer app cannot turn off a feeder.
L2
Zero-Trust Network
No implicit trust for any request, internal or external. Every API call carries a JWT, every service call is authenticated, every data access is authorised. Microsegmentation prevents lateral movement if any single service is compromised.
L3
Role-Based Access Control
Seven distinct roles: Customer-Primary, Customer-Member, Staff-Operations, Staff-Technical, Staff-Support, Management, Super-Admin. Permission checks at API layer — the frontend never receives data it is not authorised to display. Separation is architectural.
L4
End-to-End Encryption
TLS 1.3 for all API communication. AES-256 for all data at rest. Per-device PKI certificates for each STU with mutual TLS. PCI-DSS compliant payment tokenisation — Nova Grid never stores raw card data.
L5
NEXUS Fraud Detection
Statistical anomaly detection on meter consumption patterns identifies bypass and tampering attempts. All fraud flags generate immutable audit records. NEXUS never unilaterally takes punitive action — human investigators review. Confidence score displayed with every flag.
L6
Immutable Audit Trails
Every action affecting power supply, billing, or customer data is written to an append-only, cryptographically-signed audit log in a tamper-evident store. No staff, admin, or NEXUS process can modify or delete records. This is the technical foundation for anti-corruption enforcement.
L7
24/7 Security Operations
Dedicated SOC in Abuja and Lagos. SIEM integration with automated incident response playbooks. Quarterly penetration testing by independent third-party. Bug bounty programme for responsible disclosure. IEC 62351 + NIST CSF Level 4 compliance.
